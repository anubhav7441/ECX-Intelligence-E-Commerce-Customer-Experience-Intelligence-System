# Software Requirements Specification - ECX-Intelligence

## 1. Purpose and scope
ECX-Intelligence analyses e-commerce transactions and customer reviews to explain customer satisfaction, flag at-risk orders, classify complaints, and recommend actions. Scope: batch analysis of the Olist public dataset (2016-2018) plus an interactive local web application. Out of scope: live data feeds, public cloud deployment (the SaaS layer with accounts, guest demo and admin panel was added later and runs locally), paid APIs.

## 2. Users
Business/operations analyst (dashboards, recommendations); data scientist (research results, models); student/examiner (reproducible pipeline, explanations).

## 4. Non-functional requirements
| ID | Requirement | How it is met |
|---|---|---|
| NFR1 Correctness | No fabricated numbers; no target leakage; no join inflation | All numbers generated by code; leakage and join tests; clean-room reproduction identical to 6 decimals |
| NFR2 Reproducibility | One command rebuilds everything | `scripts/run_all.py`, fixed random seeds, pinned `requirements.txt` |
| NFR3 Usability | Beginner-friendly local setup | SQLite (no server), bundled Bootstrap/Chart.js (works offline), PowerShell instructions |
| NFR4 Robustness | Graceful errors | JSON errors for bad input, 404/413/500 handlers, database-down handling (tested) |
| NFR5 Security (basic) | Safe uploads and output | 20 MB limit, .csv only, in-memory validation only, upload preview rendered with textContent, figure route serves only PNGs from one folder |
| NFR6 Performance | Pages load quickly | Results pre-computed; models and reference data cached at first use |
| NFR7 Maintainability | Clear structure | Modular folders, one script per stage, docstrings, 70 tests |
| NFR8 Honesty/limitations | Limits are visible | Caveats on every analytic page and in the report |

## 5. Architecture
```
 Olist CSVs --> SQLite (SQLAlchemy) --> preprocessing --> order-level dataset (parquet)
                                                |--> statistics (SciPy/statsmodels) -----> results JSON
                                                |--> NLP rules + TF-IDF/LogReg --------> review_nlp.parquet, model
                                                |--> ML (4 models x 4 feature sets) ---> models/*.joblib, results
                                                |--> SHAP ------------------------------> figures, results
                                                \--> BI (segments, geography, recs) ---> tables, figures, results
 Flask: services (data / predict / nlp / upload)  -->  REST API + HTML pages (Bootstrap, Chart.js)
```

## 6. Data design
Tables: customers, sellers, products, orders, order_items (PK order_id+order_item_id), order_payments (PK order_id+payment_sequential), order_reviews (surrogate key review_pk because review_id is not unique), category_translation, geolocation_zip (aggregated from 1,000,163 raw rows to one row per zip prefix).
